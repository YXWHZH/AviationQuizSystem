# V1.4 实现与验收对照

依据 V1.4 需求说明书及规划阶段确认的单机多窗口、个人计分、分组共享题单与超时 0 分规则实现。

## 需求映射

| 需求 | 实现入口 |
|---|---|
| P1—P3、M1 | 公共浏览、注册、登录与工作人员初始化 |
| P4—P6、M3—M6 | 竞赛维护、预约、报名、我的竞赛、名单与分组 |
| M2、M7 | 题库、轮次题单配置、引用锁定、四选一校验 |
| P7—P8、M8—M9、C1—C3 | 分组轮次、题目发布、统一截止时间、自动判题与多态计分 |
| P9、M10、C4 | 全员个人成绩汇总、稳定排序和多窗口刷新 |
| P10、M11—M13 | 晋级预览、原子归档、历史成绩及 CSV |
| C5、R24—R29 | SQLite 事务、唯一约束、外键和完整性触发器 |

## 数据模型细化

报名与分组分别存储，选手不保存当前总分。竞赛轮次定义统一规则与题单，`group_round` 表示某组执行该轮次的状态，`question_release` 表示本组的一次题目发布及时间范围。

有效答案通过发布记录关联竞赛、轮次与题目，`answer_record` 不重复保存这三个可推导的外键。超时记录独立存储，不计入有效答题数量或用时。结束时才保存 `result` 快照。

服务返回不可变输入/视图和 DAO 查询投影。选手题目视图不含标准答案，工作人员题库查询需要有效工作人员会话。

## 事务与并发

界面线程仅操作控件，数据库操作通过共用后台队列执行。业务入口也同步串行化，保护提交、计时结算与归档顺序。每个用例共享一条事务连接，失败完整回滚。触发器再次检查分组关联、同场重复用题、发布关联、答题资格及答案/超时互斥。

时间以持久化的开始与截止毫秒时间戳为准，Timeline 只用于显示。业务服务实际受理时间等于或晚于截止时间即拒绝。重启先结算已到期题目，再继续业务操作。

选手竞赛列表附带当前账号的参与状态。预约、正式报名和比赛室入口放在可换行的固定操作区，并根据竞赛状态、报名时间和个人参与状态启用；最小窗口宽度下也保持可见。

## 验收

```powershell
./tools/apache-maven-3.9.11/bin/mvn.cmd clean test package
./tools/apache-maven-3.9.11/bin/mvn.cmd '-Dquiz.uiTest=true' test
```

结果在 `target/surefire-reports`。窗口测试只访问临时数据库，验证独立登录、分组题目隔离、提交反馈和宽窄布局；业务测试验证完整两组四名选手三轮比赛和归档恢复。

## 演示数据

`DemoDataSeeder` 在一个事务中建立 6 名选手、18 道题和 4 种状态的竞赛。待开赛决赛已经完成报名、A/B 分组、三类轮次及 9 道题的题单配置；往届赛包含最终成绩与晋级结果。固定演示编号用于幂等检查，重复运行不产生重复记录。
