# 航空知识竞赛管理系统 V1.6

JavaFX 单机课程设计。游客浏览竞赛，选手自行注册、预约及报名，工作人员分组并控制比赛。系统按个人判题、计分、排名和晋级，小组仅用于分批组织比赛。

## 环境与启动

使用 JDK 21、JavaFX 21、Maven、SQLite JDBC、JUnit 5。不需要安装数据库服务器，不实现多台电脑的网络同步。

在项目目录运行：

```powershell
./tools/apache-maven-3.9.11/bin/mvn.cmd clean test
./tools/apache-maven-3.9.11/bin/mvn.cmd javafx:run
```

本机已安装 Maven 时，也可使用 `mvn clean test` 和 `mvn javafx:run`。`tools/` 为本机工具目录，不纳入版本控制。

当前数据库已填充完整演示数据。工作人员继续使用已有账号；演示选手为 `player01` 至 `player30`，统一密码 `123456`。公共浏览、登录和各角色业务页都在同一个主窗口内切换。

需要为空白的新版数据库重新填充时运行：

```powershell
./tools/apache-maven-3.9.11/bin/mvn.cmd org.codehaus.mojo:exec-maven-plugin:3.5.0:java '-Dexec.mainClass=cn.edu.aviationquiz.service.DemoDataSeeder'
```

填充器使用固定演示编号并可重复执行；数据已存在时不会再次插入。首次建立完全空白的数据库时，仍可在公共入口初始化工作人员。

## 完整演示流程

1. 工作人员新建竞赛，填写报名开始、报名截止、比赛时间和晋级名额。时间格式为 `yyyy-MM-dd HH:mm:ss`。
2. “未开放”时选手可预约或取消预约；取消后重新预约会恢复原记录，不会产生重复记录。
3. 报名时间到后，工作人员点击“开放报名”。选手可正式报名或在截止前取消报名，重新报名会恢复原记录；正式报名后原预约自动失效。
4. 截止时间到后，工作人员点击“截止报名”，创建 A 组、B 组，将所有正式报名选手逐一分组。不允许跨竞赛或重复分组。
5. 维护四选一题库，配置必答、抢答、风险轮次及题单。同场不重复用题，各组共享题单。
6. “开始比赛”后按小组顺序“开始当前轮次 → 发布下一题 → 结束当前轮次”。本组全部轮次完成后，自动定位下一组待开始的轮次。
7. 当前组选手进入比赛室，同步倒计时并分别提交。其他组等待，不能查看或提交当前组题目。
8. 全员提交后可提前结束本题；仍有人未提交时只能等到截止时间自动结束。
9. 全部小组完成后预览晋级，确认“结束比赛并归档”。历史成绩页查询最终结果，工作人员可导出 CSV。

课堂演示可把报名结束时间设置在一两分钟后。报名状态由工作人员切换，实际报名仍受时间限制。开赛前可编辑轮次、移除题单、删除空轮次或空小组；开赛后配置锁定。

## 计分与排名

| 轮次 | 正确 | 错误 | 超时未提交 |
|---|---:|---:|---:|
| 必答 | +10 | 0 | 0 |
| 抢答 | +10 | −10 | 0 |
| 风险 | +20 | −20 | 0 |

超时不产生有效计分记录。每位选手对同一次题目发布最多有效提交一次，截止时刻及之后受理的提交无效。累计有效答题用时按 `submitted_at - question_release.started_at` 汇总。结果仅显示本人对错和分数变化，不公布标准答案。

排行榜显示全部正式参赛选手，按总分降序、答对数降序、累计有效答题用时升序、选手编号升序排序。用时按毫秒比较，页面显示秒。未答题者的总分、答对数及有效用时均为 0。最终取前 `min(N, 参赛人数)` 人晋级，不继续组织下一阶段。

## 数据与恢复

- 新数据库首次启动自动创建，当前逻辑版本为 16。
- 演示数据包含 30 名选手、60 道题和 12 场覆盖不同状态及知识分类的竞赛。
- 原有 `data/aviation_quiz.db` 完整保留，不读取或转换队伍成绩。
- 数据库是主数据源。CSV 为归档成绩副本，使用 UTF-8 BOM、引号转义并处理公式型文本。
- 关闭选手或工作人员窗口不暂停比赛；退出整个程序需要确认。
- 重启沿用原截止时间：未到期继续答题，已到期补记超时，不重复计分。
- 密码使用随机盐与 PBKDF2-HMAC-SHA256 保存。
- 被题单引用的题目内容不能修改或删除，需要复制为新题；停用不影响历史数据。

备份时先退出程序，再复制新版数据库。不要把旧版文件重命名为新版文件。

## 代码与验证

- `AppContext`：应用组装入口，创建实现类并向上层注入接口依赖。
- `ui/QuizWindows`：公共入口、单窗口角色页面、表单与比赛室。
- `controller/*Controller`：接收界面输入并调用小粒度用例接口。
- `service` 与 `service/impl`：会话权限、报名分组、比赛执行、排名归档等业务规则。
- `dao/*Dao` 与 `dao/jdbc`：核心业务的数据访问契约及 SQLite/JDBC 实现。
- `dao/Store`：JDBC 参数绑定、事务及初始化；`database/v16*.sql` 提供表和完整性触发器。
- `CompetitionRound` 子类通过多态计分，`RoundFactory` 负责可替换的规则创建。

常规测试使用临时数据库，覆盖两组四人三轮比赛、权限、去重、约束、重启恢复和归档回滚。JavaFX 窗口测试需要桌面会话，默认不运行：

```powershell
./tools/apache-maven-3.9.11/bin/mvn.cmd '-Dquiz.uiTest=true' test
```

窗口测试自动创建并关闭测试窗口，截图在 `target/ui-snapshots/`。所有测试均不使用生产数据库。设计映射见 [实现说明](docs/implementation-v16.md) 和 [核心功能分层设计](docs/layered-design.md)。

第一版提供选手自行取消和恢复预约、报名；不提供作废重赛、网络抢答及下一阶段比赛。课程设计报告应由学生本人撰写，本仓库提供程序与开发说明。
